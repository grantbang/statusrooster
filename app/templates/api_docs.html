Getting Started

Authentication

All API requests require an API key in the X-API-Key header. {% if user %} Generate one in Settings → API Keys. {% else %} Sign up to get one. {% endif %}

curl -H "X-API-Key: sr_your_key_here" \ {{ app_url }}/api/v1/monitors
headers = {"X-API-Key": "sr_your_key_here"} r = requests.get("{{ app_url }}/api/v1/monitors", headers=headers)
const res = await fetch("{{ app_url }}/api/v1/monitors", { headers: { "X-API-Key": "sr_your_key_here" } });

Response envelope: Every endpoint returns this shape:

{ "data": { ... }, // Payload (object, array, or null) "error": null, // Error string, or null on success "meta": { ... } // Metadata (count, pagination, etc.) }

Error codes:

CodeMeaning
401Missing or invalid API key
403Plan limit exceeded
404Resource not found
422Invalid or missing request body

Client Setup

All code examples on this page assume these variables are defined:

# No setup — pass the header with each request curl -H "X-API-Key: sr_your_key_here" {{ app_url }}/api/v1/monitors
# pip install requests import requests API_KEY = "sr_your_key_here" BASE = "{{ app_url }}/api/v1" headers = {"X-API-Key": API_KEY}
// Node.js or browser const API_KEY = "sr_your_key_here"; const BASE = "{{ app_url }}/api/v1"; const headers = { "X-API-Key": API_KEY };

Monitor Types

HTTP / HTTPS

monitor_type: "http"

Monitor websites and URLs for availability. Checks HTTP status code, response time, body keyword matching, and auto-detects SSL certificate expiry. This is the default monitor type.

pending up down
POST /api/v1/monitors Create HTTP monitor ▶

Provision a new HTTP/HTTPS uptime monitor. Begins checking immediately with pending status until the first check completes.

FieldTypeRequiredDescription
namestringrequiredDisplay name for the monitor
urlstringrequiredFull URL including protocol (https://example.com)
monitor_typestringoptional"http" — this is the default, can be omitted
expected_status_codeintegeroptionalExpected HTTP status code (default: 200)
timeoutintegeroptionalRequest timeout in seconds, 1–60 (default: 10)
keywordstringoptionalMark down if missing from body. Prefix with ! for "not contains". Supports AND / OR: "Welcome AND !Error"
response_threshold_msstringoptionalResponse time condition: > 2000, < 200, 200-3000
check_intervalintegeroptionalSeconds between checks, 60–300 (Pro). Free locked to 300.
alert_emailstringoptionalOverride email for alerts (defaults to account email)
alert_slack_webhookstringoptionalSlack incoming webhook URL (Pro)
webhook_urlstringoptionalPOST status changes to this URL (Pro)
publicbooleanoptionalExpose on public status page (default: true)
pausedbooleanoptionalCreate in paused state (default: false)
maintenance_windowsarrayoptionalSuppress alerts during windows (Pro). [{"day":"monday","start_utc":"02:00","end_utc":"04:00"}]
curl -X POST \ -H "X-API-Key: sr_your_key_here" \ -H "Content-Type: application/json" \ -d '{ "name": "My Website", "url": "https://example.com", "expected_status_code": 200, "timeout": 10, "keyword": "Welcome", "check_interval": 60 }' \ {{ app_url }}/api/v1/monitors
r = requests.post( f"{BASE}/monitors", headers=headers, json={ "name": "My Website", "url": "https://example.com", "expected_status_code": 200, "timeout": 10, "keyword": "Welcome", "check_interval": 60 } ) monitor = r.json()["data"] print(f"Created {monitor['id']} — status: {monitor['status']}")

Monitor REST API endpoints with deep JSON response validation. Supports Authorization headers and field-level assertions using dot-notation paths, comparison operators, and existence checks.

Heartbeat / Cron

monitor_type: "heartbeat"

Dead man's switch monitoring for cron jobs, scheduled tasks, and background workers. StatusRooster generates a unique ping URL — your service hits it on schedule. If a ping is missed beyond the grace period, the monitor transitions to down and alerts fire.

pending up down
POST /api/v1/monitors Create heartbeat monitor ▶

Provision a heartbeat monitor. No url is needed — a unique ping_url is generated automatically and returned in the response. Add this URL to the end of your cron job or scheduled task.

FieldTypeRequiredDescription
namestringrequiredDisplay name (e.g. "Nightly Backup")
monitor_typestringrequired"heartbeat"
heartbeat_intervalintegeroptionalExpected ping frequency in seconds, 60–86400 (default: 300 = 5 min)
heartbeat_grace_periodintegeroptionalExtra seconds before alerting, 0–3600 (default: 60)
check_intervalintegeroptionalCheck frequency in seconds, 60–300 (Pro). Free locked to 300.
alert_emailstringoptionalOverride alert email
alert_slack_webhookstringoptionalSlack webhook (Pro)
webhook_urlstringoptionalStatus change webhook (Pro)
publicbooleanoptionalExpose on status page (default: true)
pausedbooleanoptionalCreate paused (default: false)
maintenance_windowsarrayoptionalSuppress alerts during windows (Pro)
curl -X POST \ -H "X-API-Key: sr_your_key_here" \ -H "Content-Type: application/json" \ -d '{ "monitor_type": "heartbeat", "name": "Nightly Backup Job", "heartbeat_interval": 86400, "heartbeat_grace_period": 300 }' \ {{ app_url }}/api/v1/monitors
r = requests.post( f"{BASE}/monitors", headers=headers, json={ "monitor_type": "heartbeat", "name": "Nightly Backup Job", "heartbeat_interval": 86400, "heartbeat_grace_period": 300 } ) data = r.json()["data"] print(f"Ping URL: {data['ping_url']}")
const res = await fetch(`${BASE}/monitors`, { method: "POST", headers: { ...headers, "Content-Type": "application/json" }, body: JSON.stringify({ monitor_type: "heartbeat", name: "Nightly Backup Job", heartbeat_interval: 86400, heartbeat_grace_period: 300 }) }); const { data } = await res.json(); console.log(`Ping URL: ${data.ping_url}`);

GET POST HEAD /api/ping/{monitor_id} Record a heartbeat ping ▶

Records a successful ping and resets the heartbeat timer. If no ping arrives within heartbeat_interval + heartbeat_grace_period, the monitor transitions to down. Accepts GET, POST, or HEAD — use whichever fits your environment. No authentication required.

# Add to crontab (every 5 min) */5 * * * * curl -fsS --retry 3 {{ app_url }}/api/ping/hb_abc789 # Or with wget */5 * * * * wget -q -O /dev/null {{ app_url }}/api/ping/hb_abc789 # At the end of a deploy script curl -fsS {{ app_url }}/api/ping/hb_abc789
# At the end of your script / job import requests requests.get("{{ app_url }}/api/ping/hb_abc789")
// At the end of your scheduled function await fetch("{{ app_url }}/api/ping/hb_abc789");

Response (200 OK):

{ "status": "ok", "monitor_id": "hb_abc789", "pinged_at": "2026-03-03T12:30:00+00:00" }

💡 Tip: Use curl -fsS --retry 3 for silent operation with automatic retries on transient network errors.

SSL Certificate

monitor_type: "ssl"

Dedicated SSL/TLS certificate expiry monitoring. Connects to a domain on port 443, reads the certificate chain, and warns before expiration. The only monitor type with a warn status — triggered when the certificate is within the configured threshold of expiring.

pending up warn down

const res = await fetch(`${BASE}/monitors`, { headers }); const { data } = await res.json(); // Filter by type const httpMonitors = data.filter(m => m.monitor_type === "http"); const sslMonitors = data.filter(m => m.monitor_type === "ssl"); data.forEach(m => console.log(`${m.name} (${m.monitor_type}): ${m.status}`));
