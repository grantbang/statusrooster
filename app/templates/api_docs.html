Getting Started

Authentication

All API requests require an API key in the X-API-Key header. {% if user %} Generate one in Settings → API Keys. {% else %} Sign up to get one. {% endif %}

curl -H "X-API-Key: sr_your_key_here" \ {{ app_url }}/api/v1/monitors
headers = {"X-API-Key": "sr_your_key_here"} r = requests.get("{{ app_url }}/api/v1/monitors", headers=headers)
const res = await fetch("{{ app_url }}/api/v1/monitors", { headers: { "X-API-Key": "sr_your_key_here" } });

Response envelope: Every endpoint returns this shape:

{ "data": { ... }, // Payload (object, array, or null) "error": null, // Error string, or null on success "meta": { ... } // Optional — included on list endpoints (count, limit, etc.) }

All timestamps are UTC, formatted as ISO 8601 (2026-03-03T12:30:00+00:00).

Error codes:

CodeMeaning
401Missing or invalid API key
403Plan limit exceeded, or Pro feature used on Free plan
404Resource not found
422Invalid or missing request body

Error response example:

// 403 — Pro feature on Free plan { "detail": { "data": null, "error": "Slack alerts require a Pro plan." } } // 422 — Validation error (missing required field) { "detail": [ { "loc": ["body", "name"], "msg": "Field required", "type": "missing" } ] }

Pro-only fields (alert_slack_webhook, webhook_url, check_interval, maintenance_windows) return 403 if used on a Free plan — they are never silently ignored.

Client Setup

All code examples on this page assume these variables are defined:

# No setup — pass the header with each request curl -H "X-API-Key: sr_your_key_here" {{ app_url }}/api/v1/monitors
# pip install requests import requests API_KEY = "sr_your_key_here" BASE = "{{ app_url }}/api/v1" headers = {"X-API-Key": API_KEY}
// Node.js or browser const API_KEY = "sr_your_key_here"; const BASE = "{{ app_url }}/api/v1"; const headers = { "X-API-Key": API_KEY };

Monitor Types

HTTP / HTTPS

monitor_type: "http"

Monitor websites and URLs for availability. Checks HTTP status code, response time, body keyword matching, and auto-detects SSL certificate expiry. This is the default monitor type.

Heartbeat / Cron

monitor_type: "heartbeat"

Dead man's switch monitoring for cron jobs, scheduled tasks, and background workers. StatusRooster generates a unique ping URL — your service hits it on schedule. If a ping is missed beyond the grace period, the monitor transitions to down and alerts fire.

pending up down
POST /api/v1/monitors Create heartbeat monitor ▶

Provision a heartbeat monitor. No url is needed — a unique ping_url is generated automatically and returned in the response. Add this URL to the end of your cron job or scheduled task.

GET POST HEAD /api/ping/{monitor_id} Record a heartbeat ping ▶

Records a successful ping and resets the heartbeat timer. If no ping arrives within heartbeat_interval + heartbeat_grace_period, the monitor transitions to down. Accepts GET, POST, or HEAD — use whichever fits your environment. No authentication required.

⚠️ The ping URL is /api/ping/{id} — note there is no /v1/ in the path. This is a lightweight public endpoint, separate from the authenticated API.

# Add to crontab (every 5 min) */5 * * * * curl -fsS --retry 3 {{ app_url }}/api/ping/hb_abc789 # Or with wget */5 * * * * wget -q -O /dev/null {{ app_url }}/api/ping/hb_abc789 # At the end of a deploy script curl -fsS {{ app_url }}/api/ping/hb_abc789
# At the end of your script / job import requests requests.get("{{ app_url }}/api/ping/hb_abc789")
// At the end of your scheduled function await fetch("{{ app_url }}/api/ping/hb_abc789");

Response (200 OK):

{ "status": "ok", "monitor_id": "hb_abc789", "pinged_at": "2026-03-03T12:30:00+00:00" }

💡 Tip: Use curl -fsS --retry 3 for silent operation with automatic retries on transient network errors.

List All Monitors

GET /api/v1/monitors Retrieve all monitors for the authenticated account ▶

Returns every monitor belonging to the authenticated user — all types in a single array. Use the monitor_type field to filter client-side by type.

curl -H "X-API-Key: sr_your_key_here" \ {{ app_url }}/api/v1/monitors
r = requests.get(f"{BASE}/monitors", headers=headers) monitors = r.json()["data"] # Filter by type http_monitors = [m for m in monitors if m["monitor_type"] == "http"] heartbeats = [m for m in monitors if m["monitor_type"] == "heartbeat"] for m in monitors: print(f"{m['name']} ({m['monitor_type']}): {m['status']}")
const res = await fetch(`${BASE}/monitors`, { headers }); const { data } = await res.json(); // Filter by type const httpMonitors = data.filter(m => m.monitor_type === "http"); const sslMonitors = data.filter(m => m.monitor_type === "ssl"); data.forEach(m => console.log(`${m.name} (${m.monitor_type}): ${m.status}`));

Webhook Payloads

When a monitor's status changes, StatusRooster POSTs a JSON payload to your configured webhook_url (Pro only). Your endpoint should return a 2xx status within 10 seconds.

Headers sent with every webhook:

Content-Type: application/json User-Agent: StatusRooster/1.0

Payload shape:

{ "event": "monitor.down", "monitor_name": "My Website", "monitor_url": "https://example.com", "status": "down", "status_code": 503, "response_ms": 12045.2, "timestamp": "2026-03-03T08:15:00+00:00" }
ⓘ Webhook payload field reference
FieldTypeDescription
eventstring"monitor.down", "monitor.up", or "test"
monitor_namestringMonitor display name
monitor_urlstringMonitored URL
statusstring"up", "down", or "test"
status_codeint|nullHTTP status code (null for timeouts, heartbeat misses, SSL issues, or test events)
response_msfloat|nullResponse time in ms (null for timeouts or non-HTTP monitors)
timestampstringISO 8601 UTC timestamp

Example receiver:

# Test your webhook endpoint manually curl -X POST https://your-server.com/webhooks/statusrooster \ -H "Content-Type: application/json" \ -d '{"event":"monitor.down","monitor_name":"My Website","monitor_url":"https://example.com","status":"down","status_code":503,"response_ms":12045.2,"timestamp":"2026-03-03T08:15:00+00:00"}'
# Flask example from flask import Flask, request app = Flask(__name__) @app.post("/webhooks/statusrooster") def handle_webhook(): data = request.json if data["event"] == "monitor.down": print(f"🔴 {data['monitor_name']} is DOWN ({data['status_code']})") elif data["event"] == "monitor.up": print(f"🟢 {data['monitor_name']} is back UP") return "", 200
// Express example const express = require("express"); const app = express(); app.use(express.json()); app.post("/webhooks/statusrooster", (req, res) => { const { event, monitor_name, status_code } = req.body; if (event === "monitor.down") { console.log(`🔴 ${monitor_name} is DOWN (${status_code})`); } else if (event === "monitor.up") { console.log(`🟢 ${monitor_name} is back UP`); } res.sendStatus(200); });

💡 Use the Test Alert button on your monitor's settings page to send a test webhook with "event": "test" and verify your endpoint is working.

Rate Limits

No strict rate limits are enforced today. Please keep polling under 60 requests per minute — once per minute is sufficient for dashboard-style polling. Abusive usage may be throttled or blocked without notice.

The heartbeat ping endpoint (/api/ping/{id}) is excluded from this — ping as frequently as your cron job runs.
