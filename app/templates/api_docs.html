🐓 API Reference

Programmatic access to your StatusRooster monitors and check data.

Authentication

All API requests require an API key passed in the X-API-Key header.

{% if user %}
Generate an API key in your Settings page.
{% else %}
Sign up to get an API key.
{% endif %}
# Example: authenticate with your API key curl -H "X-API-Key: sr_your_key_here" \ {{ app_url }}/api/v1/monitors

Response format: All endpoints return JSON with this shape:

{ "data": { ... }, // The response payload (object, array, or null) "error": null, // Error message string, or null on success "meta": { ... } // Optional metadata (total count, pagination, etc.) }

Error responses use standard HTTP status codes:

CodeMeaning
401Missing or invalid API key
403Plan limit exceeded
404Resource not found

DELETE /api/v1/monitors/{id} Delete a monitor ▶

Permanently delete a monitor and all its check history.

curl -X DELETE \ -H "X-API-Key: sr_your_key_here" \ {{ app_url }}/api/v1/monitors/jkUVy3EYnvGx16jWT2v0

Example response:

{ "data": { "deleted": true, "monitor_id": "jkUVy3EYnvGx16jWT2v0" }, "error": null }

Rate Limits

The API currently does not enforce strict rate limits. Please be reasonable — if you're polling, once per minute is plenty. We reserve the right to throttle abusive usage.

Quick Start

Here's a quick Python example using requests:

# pip install requests import requests API_KEY = "sr_your_key_here" BASE = "{{ app_url }}/api/v1" headers = {"X-API-Key": API_KEY} # List all monitors r = requests.get(f"{BASE}/monitors", headers=headers) monitors = r.json()["data"] for m in monitors: print(f"{m['name']}: {m['status']} ({m['uptime_percent']}%)")

And a JavaScript example using fetch:

// Node.js or browser const API_KEY = "sr_your_key_here"; const res = await fetch("{{ app_url }}/api/v1/monitors", { headers: { "X-API-Key": API_KEY } }); const { data } = await res.json(); console.log(data);

Uptime Badges

Embed live uptime badges in your GitHub README, docs, or website. No auth required — badges are public for public monitors.

GET /badge/{monitor_id}.svg Uptime percentage badge

Returns a shields.io-style SVG badge showing the monitor's uptime percentage. Color-coded: green (≥99.5%), yellow-green (≥99%), yellow (≥95%), red (<95%).

# Markdown ![Uptime]({{ app_url }}/badge/YOUR_MONITOR_ID.svg) # HTML <img src="{{ app_url }}/badge/YOUR_MONITOR_ID.svg" alt="Uptime" />
GET /badge/{monitor_id}/status.svg Up/down status badge

Shows current monitor status: up (green), down (red), or pending (gray).

GET /badge/{monitor_id}/response.svg Response time badge

Shows the most recent response time in milliseconds. Color-coded: green (<500ms), yellow-green (<1.5s), yellow (<3s), red (≥3s).

Badges are cached for 5 minutes. Only available for monitors with public: true.
